# Как запускать `frmSettings` и почему у вас была ошибка

## Почему на скрине `Compile error: Syntax error`

1. Вы вставили строку `Attribute VB_Name = "modSettings"` прямо в модуль.
2. В VBA редакторе такую строку вручную писать нельзя (она служебная для экспорта/импорта `.bas`).

**Что делать:**
- либо удалите строку `Attribute VB_Name = ...`;
- либо импортируйте `.bas` через `File -> Import File...`.

---

## Через что запускать

Есть готовая процедура запуска формы:

- `RunSettingsOnly` из модуля `modSettings`.

### Шаги
1. Откройте VBA Editor (`Alt+F11`).
2. Убедитесь, что модуль `modSettings` и форма `frmSettings` добавлены.
3. В модуле `modSettings` поставьте курсор внутрь `Sub RunSettingsOnly()`.
4. Нажмите `F5`.

Откроется `frmSettings`, после `OK`/`Применить` настройки сохранятся в `PropertyN.ini` рядом с макросом.

---

## Минимальная интеграция с основным `main`

В начале `main` (после получения `swApp`) добавьте:

```vb
Dim settings As TMacroSettings
Dim macroFolder As String

macroFolder = Left(swApp.GetCurrentMacroPathName, InStrRev(swApp.GetCurrentMacroPathName, "\"))
LoadSettings macroFolder & "PropertyN.ini", settings

If settings.ShowSettingsOnStart Then
    If Not EditSettings(settings) Then Exit Sub
    SaveSettings macroFolder & "PropertyN.ini", settings
End If
```

И примените в ваши рабочие переменные:

```vb
Dim loadedExceptions As Object
ApplySettingsToRuntime settings, ConstructorName, loadedExceptions
Set dictExceptions = loadedExceptions
```

Это не меняет алгоритм обработки, только подгружает/применяет настройки.


## Ошибка `Variable not defined` на `mpMain`

Это значит, что в вашей форме MultiPage называется не `mpMain` (часто имя по умолчанию `MultiPage1`).

В текущем коде это учтено: сначала ищется `mpMain`, затем fallback на `MultiPage1`.

Но лучше всё равно переименовать контрол в дизайнере в `mpMain`, чтобы было единообразно.


## Если настройки "не сохраняются"

Проверить 2 момента:

1. Путь к `PropertyN.ini`.
   - Теперь используется безопасный `GetMacroFolderPath(...)` с fallback в `CurDir`, если SolidWorks не вернул путь макроса.
2. Флаг `ShowSettingsOnStart`.
   - Он больше не форсируется в `True` на каждом запуске.
   - По умолчанию окно включается только при первом запуске (когда `PropertyN.ini` ещё не существует), дальше берётся сохранённое значение.


3. Несовпадение имён контролов формы.
   - Если в `frmSettings` часть контролов названа иначе, старый код мог читать пустые значения и перезаписывать настройки дефолтами.
   - Теперь чтение в `WriteToSettings` использует значения по умолчанию из уже загруженных настроек, если контрол не найден.
4. Значения CheckBox в VBA/MSForms.
   - Для MSForms CheckBox логическое `True` это `-1`, поэтому чтение/запись чекбоксов должно идти через `CBool(...)` и `-1/0`.
5. Файл занят/нет прав на запись.
   - Сохранение теперь выполняется через временный файл `PropertyN.ini.tmp` и атомарную замену.
   - При ошибке показывается номер и текст ошибки VBA + путь к файлу, чтобы понять блокировку/права.


## Исключения: теперь без `lstExceptions`

На вкладке "Исключения и правила" используется один многострочный `txtExceptionInput`:
- вставляйте список сразу пачкой,
- одно исключение = одна строка,
- при сохранении список нормализуется (trim/lowercase, удаление дублей).


6. Сценарий "Применить -> Отмена".
   - Исправлено: `btnApply` теперь сохраняет на базе текущих загруженных настроек формы, а не на пустой структуре.
   - Поэтому после `Применить` и последующей `Отмены` значения больше не сбрасываются в 0/False.


## Матрица свойств (Удалять/Создавать)

Добавлена отдельная вкладка `pgPropsMatrix` с чекбоксами:
- `chkDel_<class>_<prop>` — какие свойства удалять,
- `chkCre_<class>_<prop>` — какие свойства создавать.

Где `class`: 1=Деталь, 2=Покупная/исключение, 3=Сборка.

Список `prop`:
1 Обозначение, 2 Наименование, 3 Полное наименование, 4 Конструктор, 5 IsFastener,
6 Длина, 7 Ширина, 8 Толщина, 9 Масса, 10 Материал, 11 Другие (только для удаления).
