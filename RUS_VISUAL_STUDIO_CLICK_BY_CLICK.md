# Визуалка на русском: пошагово «куда нажимать» для подключения PropertyN в C# add-in

Ниже — максимально практичная инструкция для русской локализации Visual Studio, без сокращений.

---

## Шаг 1. Создать проект

1. Откройте Visual Studio.
2. На стартовом окне нажмите **Создание проекта**.
3. В поиске шаблонов введите: `class library`.
4. Выберите шаблон **Библиотека классов (.NET Framework)**.
   - Важно: не выбирайте `.NET`/`.NET Core`, нужен именно `.NET Framework`.
5. Нажмите **Далее**.
6. Задайте имя проекта, например: `VasilevTaskPane`.
7. Нажмите **Дополнительные сведения** (если есть) и выберите **.NET Framework 4.7.2**.
8. Нажмите **Создать**.

---

## Шаг 2. Добавить ссылки (References)

1. В правой панели **Обозреватель решений** найдите узел **Ссылки**.
2. Нажмите правой кнопкой на **Ссылки** → **Добавить ссылку...**.
3. Добавьте:
   - `SolidWorks.Interop.sldworks`
   - `SolidWorks.Interop.swconst`
   - `SolidWorks.Interop.swpublished`
   - `System.Windows.Forms`
4. Нажмите **ОК**.

---

## Шаг 3. Добавить файл интерфейса команд

1. В **Обозреватель решений** нажмите правой кнопкой на проект.
2. Выберите **Добавить** → **Класс...**.
3. Имя файла: `ISwCommand.cs`.
4. Нажмите **Добавить**.
5. Полностью замените содержимое файла на:

```csharp
using SolidWorks.Interop.sldworks;

public interface ISwCommand
{
    string Name { get; }
    string Description { get; }
    void Execute(ISldWorks swApp);
}
```

6. Нажмите **Ctrl+S**.

> Если такой интерфейс уже есть в проекте — этот шаг пропустите.

---

## Шаг 4. Добавить файл команды PropertyN

1. Нажмите правой кнопкой на проект → **Добавить** → **Класс...**.
2. Имя файла: `SwPropertyNCommand.cs`.
3. Нажмите **Добавить**.
4. Полностью вставьте код из файла `SwPropertyNCommand.cs`.
5. Нажмите **Ctrl+S**.

---

## Шаг 5. Добавить файл шаблона add-in host

1. Нажмите правой кнопкой на проект → **Добавить** → **Класс...**.
2. Имя файла: `VasilevTaskPane_AddinTemplate.cs`.
3. Нажмите **Добавить**.
4. Полностью вставьте код из файла `VasilevTaskPane_AddinTemplate.cs`.
5. Нажмите **Ctrl+S**.

---

## Шаг 6. ВАЖНО: делаем без сложного «перенесите логику»

Если вы новичок и не хотите разбираться в C#-коде, делайте **только так**:

### Вариант А (рекомендуется, самый простой)

1. Оставьте ваш старый `SwAddin.cs` как есть (не трогайте).
2. В проект добавьте **только** файл `SwPropertyNCommand.cs`.
3. На этом этапе **НЕ добавляйте** `VasilevTaskPane_AddinTemplate.cs` в проект.
4. Сначала добейтесь, чтобы проект просто собирался без ошибок.

> Это безопасно: вы не получите дубли `SwAddin`, `TaskPaneHost`, `ComVisible`, `Guid`.

### Вариант Б (если хотите новый хост из шаблона)

Только если готовы заменить старый хост:

1. Сделайте копию проекта (backup).
2. Удалите старый `SwAddin.cs` и старый `TaskPaneHost.cs`.
3. Добавьте `VasilevTaskPane_AddinTemplate.cs`.
4. Проверьте сборку.

> Если вы не уверены — используйте **Вариант А**.

---

## Шаг 7. Добавить иконку для TaskPane

1. Нажмите правой кнопкой на проект → **Добавить** → **Существующий элемент...**.
2. Выберите файл `icon.bmp`.
3. Выделите `icon.bmp` в проекте и откройте окно **Свойства**.
4. Установите:
   - **Действие при сборке** = `Содержимое`
   - **Копировать в выходной каталог** = `Копировать, если новее`

---

## Шаг 8. Проверить COM-атрибуты

Проверьте, что у классов есть:

1. Для add-in класса:
   - `[ComVisible(true)]`
   - `[Guid("...")]`
2. Для `TaskPaneHost`:
   - `[ComVisible(true)]`
   - `[Guid("...")]`
   - `[ProgId("VasilevTaskPane.TaskPaneHost")]`

---

## Шаг 9. Собрать проект

1. В верхнем меню нажмите **Сборка** → **Собрать решение**.
2. Дождитесь статуса `Сборка завершена успешно`.
3. Если есть ошибки — сначала исправьте их, потом снова соберите.

---

## Шаг 10. Запуск Visual Studio от администратора (важно)

Поскольку регистрация add-in пишет в HKLM:

1. Закройте Visual Studio.
2. Нажмите правой кнопкой по Visual Studio → **Запуск от имени администратора**.
3. Откройте проект снова.
4. Повторите **Сборка** → **Собрать решение**.

---

## Шаг 11. Подключить add-in в SolidWorks

1. Откройте SolidWorks.
2. В меню выберите **Сервис** → **Надстройки**.
3. Найдите ваш add-in (например, `Vasilev TaskPane`).
4. Поставьте галочку в колонке **Активные надстройки**.
5. При необходимости поставьте галочку в **Запуск**.

---

## Шаг 12. Проверка, что всё подключилось

1. Откройте TaskPane справа.
2. Выберите вкладку `Vasilev Tools`.
3. Должна быть кнопка `PropertyN`.
4. Нажмите `PropertyN`.
5. Должно открыться окно настроек, затем прогресс-окно обработки.

---

## Шаг 13. Частые ошибки

### Ошибка 1: «Не найден ISwAddin»
- Не добавлена ссылка `SolidWorks.Interop.swpublished`.

### Ошибка 2: «Не найден ISldWorks»
- Не добавлена ссылка `SolidWorks.Interop.sldworks`.

### Ошибка 3: Кнопка есть, но при нажатии ничего
- Не добавили `new SwPropertyNCommand()` в `BuildCommands()`.

### Ошибка 4: TaskPane не открывается
- Проверьте `icon.bmp` и путь к нему.

### Ошибка 5: add-in не регистрируется
- Visual Studio запущена не от администратора.

---

## Минимум файлов, которые реально нужны

1. `ISwCommand.cs` (если уже есть — не добавлять повторно)
2. `SwPropertyNCommand.cs`
3. `icon.bmp`

Для новичка этого достаточно, чтобы не словить конфликт классов.
`VasilevTaskPane_AddinTemplate.cs` используйте только когда будете готовы заменить старый хост целиком.



## Шаг 14. Если получили именно такие ошибки компиляции (как у вас)

Ниже короткий разбор ваших сообщений и что сделать:

1. **"Повторяющийся атрибут ComVisible/Guid"**
   - Причина: у вас в проекте ДВА класса с одинаковыми COM-атрибутами (`SwAddin`, `TaskPaneHost`).
   - Решение: оставьте только один рабочий `SwAddin` и один рабочий `TaskPaneHost`.

2. **"Пространство имен VasilevTaskPane уже содержит определение для SwAddin/TaskPaneHost"**
   - Причина: в проект добавлен второй файл с теми же именами классов.
   - Решение: удалите/исключите дублирующий класс, либо переименуйте его.

3. **"Тип SwAddin уже определяет ConnectToSW/DisconnectFromSW/RegisterFunction/UnregisterFunction"**
   - Причина: тот же класс объявлен дважды.
   - Решение: должен остаться только ОДИН класс `SwAddin`.

4. **"Не удалось найти тип или имя пространства имен VasilevTools"**
   - Причина: в коде стоит `using VasilevTools.Commands`, но такого namespace в проекте нет.
   - Решение: либо исправьте namespace команды, либо используйте корректный `using` под ваш проект.

5. **"Не удалось найти тип SwPropertyNCommand"**
   - Причина: файл `SwPropertyNCommand.cs` не добавлен или у класса другой namespace.
   - Решение: проверьте, что файл есть в проекте и `BuildCommands()` видит этот класс.

6. **"Неоднозначный вызов TaskPaneHost.TaskPaneHost()"**
   - Причина: два одинаковых класса `TaskPaneHost`.
   - Решение: оставить только один `TaskPaneHost`.

### Что сделать прямо сейчас (быстрый фикс)

1. В `Обозреватель решений` найдите дубли `SwAddin`/`TaskPaneHost`.
2. Оставьте ваши рабочие классы, а шаблонный файл используйте только как пример.
3. Убедитесь, что в проекте есть ровно один файл с `class SwAddin`.
4. Убедитесь, что в проекте есть ровно один файл с `class TaskPaneHost`.
5. Проверьте namespace у `SwPropertyNCommand` и подключите правильный `using`.
6. Снова нажмите `Сборка -> Собрать решение`.
